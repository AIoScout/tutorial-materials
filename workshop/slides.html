Why this matters

The car has to read the road

On the AIoScout playfield, the robot car meets road signs: turn left, turn right, stop. A line-follower can follow a track — but deciding what a sign says is a job for a different kind of program.

Today's question: how do you make a chip with kilobytes of memory tell a left arrow from a right arrow, reliably, in real time?

Detection vs. decision

Sensors answer "how far"

Ultrasonic and IR sensors measure the world — but they can't read symbols. Images are richer and harder.

Where the AI runs

On the car, not the cloud

No Wi-Fi, no round trip — the camera and the decision stay on one chip. That's edge AI.

Concept 01

Rules vs. learning

A normal program follows rules a human wrote. But try to write rules for "this pixel pattern is a left arrow" — different distances, angles, lighting, shadows. Impossible by hand.

Machine learning flips the direction: you provide labeled examples — images with the correct answer attached — and the computer learns the rules itself. That process is training.

Classic programming

Rules + data → answers

Works for LEDs and motors. Breaks on messy real-world images.

Machine learning

Data + answers → rules

The machine writes the rules. You steer it with the data you collect.

Concept 02

What "training" actually is

  • You show the network thousands of samples — tiny images, each tagged with its class
  • After every batch, the network adjusts itself to reduce its mistakes
  • One full pass over the dataset is an epoch — training runs many epochs
  • A held-out slice of data (validation split) is used to check the model on images it hasn't trained on

Key idea  the quality of your samples decides the quality of your model — long before any hyperparameter does.

The output

A confidence per class

left arrow 91% ███ winner right arrow 7% ▌ wall 2% ▏

The car acts on the highest class — your job is making the winner clearly ahead.

Concept 03

The CNN, in one picture

A Convolutional Neural Network is a stack of small feature detectors. Early layers spot edges and blobs; deeper layers combine them into shapes; the last layer turns shapes into class confidences.

  • Filters = the detectors (more filters = more patterns, bigger model)
  • Dense units = the decision layer
  • Every number here is a knob you'll set in the app

Today's architecture

input 96×96 grayscale ↓ Conv1 — 8 filters // edges, blobs ↓ Conv2 — 16 filters // shapes, strokes ↓ Dense — 32 units // decisions ↓ confidence per class // left / right / stop…

Tiny by AI standards — exactly the size a microcontroller can run in real time.

Concept 04

Fitting AI onto a chip

  • Quantization to int8 — 1 byte per number instead of 4: ~4× smaller and faster, negligible accuracy cost
  • TensorFlow Lite Micro — Google's runtime for microcontrollers; the core fits in 16 KB, no OS needed
  • ESP32-P4 — dual-core SoC with camera support, programmed via Arduino IDE

The model you export today is a C array compiled into the firmware — no internet involved at runtime.

The pipeline

Six steps

Collect → Preprocess → Train → Preview → Export → Deploy. Everything today maps onto these six.

Data craft 01

Collecting good samples

  • One class per thing to recognize — "left", "right", "stop"
  • 30–50 samples per class, counts roughly equal
  • Vary distance, angle, position in frame, lighting while capturing
  • Capture from the same camera the model will use — the board's camera, not your laptop's
  • Delete blurry or accidental shots — they teach wrong things

Data craft 02

Preprocessing: crop and clean

  • ROI — the crop box; only this region reaches the model
  • Dark Thr — darker pixels → pure white (kills shadows and sleeves)
  • Lum Thr — brighter pixels → pure white (kills glare)
  • Auto mode crops the darkest region for you; Manual ROI gives you the box
  • Press S to save — unsaved preprocessing is lost

Rule of thumb  the sign is black, the background is white. Everything else is noise.

Data craft 03

Hyperparameters, and which ones matter today

ParameterDefaultEffect
Image size96Detail vs. speed (96 / 160 / 384)
Batch size16Samples per update; bigger = faster, more RAM
Epochs20Passes over the data; too many → overfitting
Validation split0.25Fraction held out for checking
Learning rate0.001Step size; higher = faster, unstable
Conv1 / Conv2 filters8 / 16Feature detectors per layer
Dense units32Decision-layer neurons

Start from defaults

Change one thing at a time

Defaults work well for 96×96 grayscale. For the project, the highest-leverage changes are in your data, not these numbers.

The trade-off

Bigger ≠ better here

More filters/units/size may add accuracy — always at slower inference. On a microcontroller, speed is part of correctness.

Concept 05

Overfitting: memorizing vs. learning

A model can ace every training photo and still fail on the first new photo it sees — it memorized instead of learning. Like a student who memorizes past papers.

  • Watch: validation accuracy during training
  • Prevent: more variety in samples (angles, lighting), moderate epochs
  • Final test: images from outside your team — you'll do exactly this in the project

Healthy

Training ≈ validation

Both scores track each other upward. The model generalizes.

Overfit

Validation stalls or drops

Training keeps climbing while held-out performance falls. Stop, get more varied data, retrain.

Your turn · data craft

Five tips that decide your score

Tip 01

Thick marker, big digits

8–10 cm tall, bold strokes. Thin pen lines vanish at 96×96 grayscale.

Tip 02

Capture from the board

Use Device, not the webcam — train on images from the camera that will run the model.

Tip 03

Equal counts

30–50 per class, balanced. An unbalanced set biases the model to the biggest class.

Tip 04

Test on strangers

The evaluation uses another team's handwriting. Include a teammate's hand in training data variety.

Tip 05  iterate — train, test, fix the data, retrain. Two or three loops are normal; that's the engineering.
