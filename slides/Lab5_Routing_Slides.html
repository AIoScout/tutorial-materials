The math · graphs

Graphs are everywhere

In mathematics a graph isn't a bar chart — it's dots (nodes) joined by lines (edges).

  • MTR map — stations & train lines
  • Street map — intersections & roads
  • Social network — people & friendships

Give every edge a number — distance, time, toll — and you have a weighted graph. Weights = cost.

The algorithm

Dijkstra in three steps

Move 01 · Initialize

Start = 0, rest = ∞

The source node's distance is zero; every other node starts at infinity — "no route known yet".

Move 02 · Explore

Visit the nearest

Pick the unvisited node with the smallest distance. If going through it shortens a neighbour's route — update it.

Move 03 · Repeat

Until you arrive

Keep visiting the nearest unvisited node until all are visited — or your target is reached.

Invented by Edsger Dijkstra in 1956 — and still running inside your phone's map app today.

Dijkstra step by step

Find A → D in five steps

StepWe visitWhat we checkA · B · C · D after
1—initial state0 · ∞ · ∞ · ∞
2A (0)A→B: 3 ✓   A→C: 10 ✓0 · 3 · 10 · ∞
3B (3)B→C: 3+4=7 < 10 ✓ update   B→D: 3+8=11 ✓0 · 3 · 7 · 11
4C (7)C→D: 7+2=9 < 11 ✓ update0 · 3 · 7 · 9
5D (9)done0 · 3 · 7 · 9

Backtrack  D ← C ← B ← A: the path is A → B → C → D, cost 9 — the "detour" beats the direct-looking routes (11 and 10).

Part II · FreeRTOS

Superloop vs. FreeRTOS

So far your sketches ran a superloop — one thing at a time, forever. But if the Wi-Fi code hangs waiting to reconnect, line-following dies with it.

That's like refusing to start homework until the washing machine finishes — even though it runs by itself.

FreeRTOS is a tiny real-time operating system: many tasks switching so fast they look simultaneous — and the ESP32 has two cores: two workers running tasks truly at once.

Superloop

Sequential

Read sensors → think → move → repeat. One traffic jam stops everything.

FreeRTOS

Concurrent

Sensor task, movement task, network task — scheduled with priorities, side by side.

Part II · FreeRTOS

A task is a mini-sketch

void Blink(void *pvPara) { // pvPara must exist! pinMode(LED1, OUTPUT); // setup part — runs once while (true) { // running part — forever digitalWrite(LED1, HIGH); vTaskDelay(100); // not delay()! digitalWrite(LED1, LOW); vTaskDelay(200); } } // in setup() — hand the task to the MCU: xTaskCreatePinnedToCore(Blink, "Blinking", 2000, NULL, 1, &BlinkTaskHandle, 1); // │fn │name │stack │par │pri │handle │core

Rule 01

void *pvPara — always

Even when unused, the parameter must be there. It's the template's signature.

Rule 02

vTaskDelay() every round

Use vTaskDelay(), never delay(). Without it the task hogs its core and never actually runs on the MCU.

Part II · Line tracking

Three IR sensors under the car

Each IR sensor shines light at the floor and measures the bounce:

Black surface

Absorbs light → 1

Little reflection — output reads HIGH (1).

White surface

Reflects light → 0

Lots of reflection — output reads LOW (0).

  • Middle sensor on the line → keep going forward
  • Left sensor on the line → drifted right → turn left
  • Right sensor on the line → drifted left → turn right

Part II · Task 5

The crossroad decision

  • Start the car at the left side of the track
  • After 1–2 s the car starts moving
  • At the crossroad: turn right, follow the left track
  • Stop at the end line

Hint  a junction makes all sensors see the line at once — that's your cue to rotate instead of stop. A short delay before the turn helps too.
