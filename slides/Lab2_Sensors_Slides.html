The brain

The ESP32-S3 is a tiny computer

A microcontroller is a whole computer on one chip — weaker than your phone, but perfect at reading sensors and driving motors, and it sips battery power.

Sensors are the eyes and ears, motors are the muscles, and the ESP32 is the brain that decides what to do.

240 MHz CPU Wi-Fi + Bluetooth GPIO pins ×30+

While it runs your code

240 MHz

That's 240 million steps every second — plenty to ping sensors thousands of times a second.

01

Task 1 · HC-SR04 ultrasonic sensor

Distance by echo

TRIG — send SOUND — travels BOUNCE — reflects ECHO — listen

Sound above 20 kHz — ultrasound you can't hear — becomes a measuring tape.

The idea

Bats shout. Then they listen.

Bats can't see well, so they send high-pitched sounds and time the echo. Quick echo → close wall. Slow echo → far wall.

The HC-SR04 plays the same trick: a transmitter "shouts" a 40 kHz pulse, a receiver hears the echo, and the chip times the round trip.

Key insight  distance isn't measured — it's calculated from time.

The math

Distance is time × speed

The formula

Distance =

speed of sound × time interval 2

Speed of sound in air ≈ 343 m/s at room temperature.

Worked example

Echo returns after 588 µs (0.000588 s):

343 × 0.000588 ÷ 2

≈ 10 cm

Why ÷ 2?

The sound travels to the object and back again — you hear twice the distance.

Halve the round trip to get the one-way distance.

Wire it

Two pins, one shout, one ear

// Task_1.ino — match your pinout diagram #define trigPin 39 // GPIO that SENDS the pulse #define echoPin 38 // GPIO that WAITS for the echo #define SOUND_SPEED 343 // metres per second // after pulseIn() measures the echo time: distance = (duration * SOUND_SPEED) / 2;

02

Task 2 · ICM-42688-P inertial measurement unit

Feeling motion

Accelerometer — push & gravity Gyroscope — spin rate Filters — trust

The chip that keeps drones level and phones knowing which way is up — now in your car.

The chip

Three senses on one chip

Accelerometer

Feels push & gravity

Linear acceleration in m/s². Standing still, it still feels gravity (9.81 m/s²) — that's how it knows "down". Like feeling pushed in a bus.

Gyroscope

Feels spin rate

Angular velocity in °/s — how fast you're rotating around each axis. Your inner ear, digitised.

Magnetometer · optional

Feels north

Magnetic field strength in µT — a digital compass. Not needed today.

The problem

Two estimates — both half-right

Gyroscope · integrate spin

Fast, smooth, quiet — but integrating piles up tiny errors, so the angle drifts away over time.

Accelerometer · read gravity

Stable forever — gravity never lies — but every bump and shake makes it noisy.

The fix  gyro for this instant, accelerometer for the long run — together.

The fix

Two filters, used together

Low-pass filter — smooth the noise

Keep the slow signal (gravity), drop the fast junk (vibration). Each step, blend the new reading into the old average:

filtered = α·new + (1−α)·old α = 0.3: 0.3×20 + 0.7×10 = 13 // moves smoothly

Too much filtering → the value lags behind reality.

Complementary filter — sensor fusion

One weighted blend of both estimates — trust the gyro short-term, the accelerometer long-term:

angle = α·(gyro estimate) + (1−α)·(accel estimate) // α ≈ 0.95: mostly gyro, gravity corrects drift

This is real sensor fusion — the trick inside drones and game controllers.

The code

The code, annotated

// meet the chip — it speaks I2C ICM42688 IMU(Wire, 0x68, IMU_SDA, IMU_SCL); IMU.setAccelFS(ICM42688::gpm8); // ±8 g range IMU.setGyroFS(ICM42688::dps500); // ±500 °/s // in the loop — the whole idea in 3 lines: filteredX = 0.3f*IMU.accX() + 0.7f*filteredX; // 1 low-pass roll = 0.95f*gyro_roll + 0.05f*acc_roll; // 2 blend
